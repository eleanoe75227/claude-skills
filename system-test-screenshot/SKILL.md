# 系統功能測試截圖（Playwright）

實機測試：登入系統 → 依素材逐步操作＋紅框標註截圖 → 插回 Word 或產測試報告。
大型系統測試（如年度測試報告）、修 bug 更版前驗證、功能／權限測試都走這支。
本檔只放「怎麼做」。原理／selector 庫寫法／踩雷在 `REFERENCE.md`，**卡住才讀**。

## 開工時先跟使用者說（需要使用者提供的資料）
素材不綁專案，依拿到的素材決定走哪個流程：

| 使用者給的素材 | 走哪個流程 | 預期結果從哪來 |
|---|---|---|
| 測試步驟文件（Word：步驟＋空截圖槽） | 流程B | 步驟文件本身 |
| 雛形說明簡報／變更需求說明／bug 單 | 流程C（自行設計測試） | 簡報或需求敘述；bug 單＝修正後應有的行為＋回歸 |
| 測試計畫書／既有測試報告（含案例表、預期結果） | 流程D（照文件逐項執行） | 文件內的預期結果；報告格式沿用該文件 |
| 只要截某幾頁 | 流程A | — |

另外每次都要確認（缺的一次列出來，素材齊的部分先做）：
- **環境**：哪個系統、測試機或正式機、網址；要不要開 VPN。
- **帳號**：需要哪些角色。帳密請使用者自己填本機 `.env`（格式見 `roles.py` 開頭），**嚴禁在對話中打密碼**。
- **測試資料與寫入**：用哪一筆資料、會不會寫入、測完要不要還原。**正式機要寫入前一定先問**。
- **交付形式**：插回原 Word／獨立測試報告／機關指定格式。
- **測試範圍**（修 bug 更版）：這次改了什麼，加上要做回歸測試的相關功能。

## 檔案
| 檔 | 用途 |
|---|---|
| `roles.py` | 通用多角色登入（各角色各存一份 session；失效彈窗、帳密自動填好、人工輸驗證碼）；`--check` 檢查各角色是否同帳號、session 是否有效 |
| `capture.py` | 批次截頁（用 roles.py 登入）；`--role`、`--out` |
| `annotate.py` | 紅框＋箭頭標註（`from annotate import annotate_page as redbox`）；多個動作點用 `annotate_multi`（編號框、不畫箭頭）；操作手冊用 `annotate_manual`（細框＋編號圓圈） |
| `excel_shot.py` | macOS 背景開 Excel 截圖（自動點掉格式對話框，不搶前景）；需 pyobjc Quartz，裝不起來就改 LibreOffice 轉 html/PDF 再截 |
| `assist_login.py` | 正式機協作登入（使用者本人操作，如自然人憑證／單一簽入）＋每次換頁自動截圖；成功／出現提示字樣／閒置／總時限任一成立就結束 |
| `report_status.py` | 測試報告 docx 截圖格盤點：已插圖／待補／【說明】／空白／【請SA確認】格數，`--detail` 列缺哪幾格 |
| `.env` | 帳密與登入設定（**務必 gitignore**） |

需求：`pip install playwright pillow python-docx` ＋ `playwright install chromium`。

## 前置檢查（每次開工）
1. 連線：`curl -k -s -o /dev/null -w "%{http_code}" --max-time 10 <登入頁網址>` → 必須 `200`，否則請使用者開 VPN。
2. 帳密：確認 `.env` 必要鍵非空（只檢查有無值，不印內容）。多角色測試另跑 `python3 roles.py --check`。

## 流程A｜批次截頁
```bash
python3 capture.py 名稱=URL 名稱2=URL2
```
- 名稱結尾加 `*`＝整頁截；預設 1920×1080 可視範圍。
- 印出「請在彈出視窗完成登入」＝session 過期，**等使用者在視窗登入即可**，程式會自己接手。

## 流程B｜測試步驟 Word 自動截圖
Word 格式約定：**非空段落＝測試步驟，緊接的空段落＝截圖槽**。

1. 讀使用者的 Word → 列出步驟清單，向使用者確認理解正確。
2. 在暫存區寫腳本，每一步固定三件事：
   `定位元素` → `redbox(page, 元素.bounding_box(), 圖路徑)` → `執行動作(點擊/填值)`。
   selector **先查 REFERENCE.md 的 selector 庫**；沒有才偵察（用 REFERENCE 的偵察範本），偵察到的新 selector **任務結束前補回 selector 庫**（含驗證日期、前置條件）。同一個元素猜到第 3 次還不對就停，改用偵察範本看實際 DOM。
3. 步驟含「匯出／下載／開啟檔案確認」：攔下載存檔 → `python3 excel_shot.py <下載檔> <輸出png>`
4. 插圖規則：插在步驟段落後的空段落；`width=Cm(15.5)`；**該段落必設單行間距**（否則圖被固定行高截斷）；最後一步若無空段落就 `add_paragraph()` 補一段。
5. 成品另存新檔（來源檔不動）給使用者確認。

## 流程C｜依簡報／需求／bug 單自行設計測試＋測試報告
適用：沒有現成測試案例，使用者給雛形說明簡報、變更需求說明或 bug 單，要「進系統測＋寫測試報告」。

1. **讀素材 → 列出「能做／不能做」**：簡報或需求的說明就是預期結果；bug 單則列出「修正點＋可能受影響的相關功能」。
2. **開工前問清楚**（見上方〈開工時先跟使用者說〉）：
   - 各角色帳號：填完跑 `roles.py --check`。同一組帳號不能當兩個角色；角色不夠時，同一個帳號分「設定前／設定後」兩種身分測。
   - 測試用哪一筆資料、測完要不要還原。
3. **測試設計**：正向流程（bug 單則是修正點重現＋確認已修好），加上四類固定要測的項目：
   - 反向：權限設定前沒有權限（選單沒出現；直接開網址被拒）
   - 越權：按鈕隱藏之後，再用 `page.evaluate(...)` 或網址直接開別人的資料
   - 前後比對：異動前後各截一次
   - 管理員回歸：管理員原本的權限沒有受影響
4. **操作截圖**：`roles.get(p, 角色)` 取頁面；截圖依主題＋日期分資料夾，留 `_raw.png` 原圖方便重標。單一動作用 `annotate`，多個動作用 `annotate_multi`（圖說用①②③）。截完開圖目視檢查。
5. **測試報告**（精簡版給機關承辦人）：封面 → 一、測試說明 → 二、測試結果表（能做／不能做／管理員，結果「符合」）→ 三、操作畫面（每節一句＋1～2 圖）。
   - **不放**：逐項前置條件／步驟／預期／實際表、待確認、未涵蓋範圍等內部用語。
   - 內部發現（設計疑點、既有 bug、簡報截圖錯誤）不進對外報告，寫進對內彙整（見〈判定與佐證紀律〉第4點）。
   - 機關有指定報告格式時，以機關格式為準。

## 流程D｜照測試計畫書／既有測試報告逐項執行
適用：已經有案例表與預期結果（例：年度系統測試報告）。
1. 讀文件 → 列出案例清單（編號、角色、前置條件、預期結果），**標出哪些案例的前提目前不成立**（測試機沒更版、缺資料、缺帳號），跟使用者確認範圍。
2. 逐項操作截圖（步驟同流程B的 `定位→redbox→動作`），判定照〈判定與佐證紀律〉。
3. 報告**沿用原文件格式**插圖、填結果；需 SA 拍板的寫紅字【請SA確認】，寫進文件，不要只在 issue 系統提。
4. 另存新檔（來源檔不動），加上對內彙整。
5. **每輪補圖後跑 `report_status.py <報告> --detail`**，格數直接貼對內彙整與回報，不要手數。
6. **收尾排版驗證**：插圖後看一次版面（圖與說明是否跨頁分開、表格是否被撐破）。LibreOffice 轉 PDF 只能粗看；要以 Word 為準就用 Word 轉。驗不了就明講「排版未驗證，請用 Word 看第 X 項」。

**特殊操作**
- **要改系統共用設定才能測**（例：送件截止時間）：寫一支「讀原值 → 改 → 測＋截圖 → 改回原值 → 讀回確認已還原」的腳本，請使用者自己跑；腳本**一定要 try/finally 改回**，並在對內彙整記下改動時間與還原結果。
- **正式機需本人身分登入**：用 `assist_login.py <起始網址> <輸出資料夾> --host <系統主機>`；含網址列的整窗截圖另用 `screencapture -l`。

## 判定與佐證紀律（所有流程都適用）
1. **判定分四種，不可混**（內部紀錄一律標；對外報告依機關格式換成對應用語）：
   | 判定 | 什麼時候用 | 必填說明 |
   |---|---|---|
   | ✅ 通過 | 畫面結果與預期相符 | — |
   | ❌ 未通過 | 前提成立、確實操作到，結果不符預期 | 預期 vs 實際 |
   | ⏭ 未執行 | **前提不成立**：測試機未更版、缺測試資料/帳號、上一步被擋 | **缺什麼才能解鎖** |
   | ⚪ 非缺陷 | 看似異常，其實是設計如此、資料狀態造成、或無法重現 | 為什麼不算缺陷 |
   測試機沒更版、前置資料造不出來 → 標「未執行」，**不可標「未通過」**，也不可開成缺陷單。
   **非實機來源的佐證**：
   - **雛形站截圖**（功能未上線、使用者同意先用雛形交）：可當畫面示意，但判定仍是「⏭ 未執行」，解鎖條件寫「待功能上線後以實機畫面補驗」；對內彙整一定要標。
   - **他人提供的截圖**（開發者在 issue 貼圖等）：可插報告，紅框照自己標準重畫，判定依圖內容照常判，對內彙整註明來源。圖說與內容不符時以畫面內容為準。
2. **有寫入的步驟要讀回來確認**：「儲存成功」提示不算數，要**重新載入頁面（或換角色開同一筆）截到值真的在**才判通過。
3. **判定以畫面為準**：原始碼、API 回應只能當線索，寫成「推測」；截圖或畫面文字才是證據。實測推翻先前推測時，主動說明哪個前提錯了。
4. **每次測試產兩份**：
   - **對外**：機關要的測試報告（docx），只放結果與佐證畫面。
   - **對內**：`<報告名>_內部彙整_<yymmdd>.html`（或 .md），收未通過、未執行（含解鎖條件）、待 SA 確認、設計疑點、既有 bug、截圖待重驗、issue 單號。對話中講過的內部發現也要寫進來。
5. **說「功能沒做/防呆沒做」前先走三段**（見 REFERENCE §5），沒走完只能寫「本次未觀察到」。

## 錯誤對照表（先查這裡）
| 症狀 | 處置 |
|---|---|
| 畫面沒有樣式、像手機版 | 沒設桌機 UA（roles.py 已內建；自己寫 new_context 要帶 `user_agent=UA`） |
| 網址被導回 login 或逾時頁 | session 過期 → 跑 `python3 roles.py <角色>`，等使用者在彈窗登入 |
| element not visible／找不到元素 | 查 selector 庫；展開面板後原按鈕常被藏，改用面板內的按鈕 |
| 下載的 xlsx 報 BadZipFile | 匯出檔常是 HTML 假 xlsx → 走 excel_shot.py，不要用 openpyxl 硬開 |
| excel_shot 截出很小的圖 | 對話框沒點掉；按鈕名比對用 starts with |
| excel_shot 完全失敗 | 終端機 App 需「螢幕錄製＋輔助使用」權限，見 REFERENCE §4 |
| 插入 Word 後圖被壓扁 | 該段落忘了設單行間距 |
| 同名元素多個、first 點錯 | 改用 `[onclick*=...]`／title 等屬性定位 |

## 資安底線（強制，違反即停）
- 帳密只存本機 `.env`；程式與回覆**都不印密碼**。`.env`、session 檔、截圖、產出的 docx 一律不進 git。
- **正式機／含個資截圖**（身分證字號、本人帳號、公司名）：插報告前先打碼；不能用的原圖移到 `_勿用/` 子資料夾，不要跟可用圖混放；報告定版後含個資的原圖一併刪除。
