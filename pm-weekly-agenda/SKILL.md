# PM 週會議程 Skill

## 開工時先跟使用者說（需要使用者提供的資料）

**固定來源（第一次使用時把下面兩個連結換成自己的來源表；連結有變動時再更新）**
- 議程來源：`<議程來源檔>` <議程來源 Google Sheets 連結> （若本身是xlsx，下載不用exportMimeType；Claude不寫回來源表）
- 輪值表：`<值日生輪值表>`（分頁「115年(會議輪值表)」）<值日生輪值表 Google Sheets 連結> （原生試算表，要加exportMimeType轉xlsx；與議程來源不同檔，主席/值日生由Claude讀出後填config）

開工一次問齊：
1. 會議日期（週四；週二是否照常開，或取消全部併週四）
2. 本週請假／出差的PM
3. 上半場順序有無指定、重點專案裡對不到總表PM的項目歸誰
4. 已離職但總表還沒刪的人、總表沒有但要加進下半場的人（例：PM_R、PM_A）
5. 輪值表上的值日生若已離職，誰代（Claude讀輪值表後先對照下方「已離職名單」，對到就主動問，不等使用者發現）


## 任務說明

將使用者提供的 PM 會議原始 xlsx，依照固定格式產出當週正式議程 xlsx。

來源說明：原始資料為 Google Sheets。**兩種取得方式都支援**：
1. **使用者直接貼 Google Sheets 連結（2026-09-14起優先，不用使用者手動下載）**：從連結取出 fileId（`.../d/<fileId>/edit...`），流程：
   - `mcp__claude_ai_Google_Drive__get_file_metadata`（fileId）先確認檔名/mimeType，判斷是原生 Google試算表(`application/vnd.google-apps.spreadsheet`)還是本來就是xlsx(`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`)
   - `mcp__claude_ai_Google_Drive__download_file_content`（fileId，原生試算表要加 `exportMimeType: "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"`）
   - 檔案較大時工具會回傳「內容存到某個 tool-results .txt」而非直接吐字串，那個檔案是 `{content, id, mimeType, title}` 的 JSON，`content` 是 base64——用 python 讀 JSON、`base64.b64decode` 寫成 `.xlsx` 存到 scratchpad，不要用 Read 工具整份讀那個 txt（會佔用大量 context）
   - 主席／值日生的「115年(會議輪值表)」有時是**另一個獨立的 Google Sheets 連結**（跟主要來源表不同檔案），一樣用上述流程單獨抓下來讀取即可，不用勉強塞進同一個 source_xlsx（見下方「115年(會議輪值表)」列的說明）
2. **使用者自己先下載 xlsx 再給路徑**：舊流程，一樣支援，直接讀取路徑即可

## 來源檔案結構

使用者提供的來源 xlsx（例：`活頁簿1.xlsx`）固定含以下分頁，**先列出所有分頁名稱，再依內容結構判斷各分頁角色，不依賴固定名稱**：

| 分頁角色 | 識別方式 | 用途 | 取得方式 |
|---|---|---|---|
| **重點專案** | 僅一欄，A1含會議日期與主席資訊，以下為編號專案清單 | 本週由主管會議決定的列管專案，每週異動 | 固定來源自動讀 |
| **專案總表(正常報告版)** | A1含「週二報告(正常)」，中段另有「週四報告(正常)」標題 | 所有PM完整專案清單，人員名稱與專案內容主庫 | 固定來源自動讀 |
| **專案議程** | A1含「週二報告」，並有「週四報告(上半場主管)」「週四報告(下半場正常)」等標題 | 本skill的輸出對象，會被腳本整個清空重寫 | 不用給——分頁不存在時腳本會自動建立（2026-08-31確認可省略） |
| **範例日期分頁**（如`1150715`） | 名稱為民國日期格式，A1為`【115-MM-DD會議議程】` | 純格式參考（單欄A排版） | 不用給——已內建於`template/agenda_format_ref.json` |
| **「115年(會議輪值表)」** | A1含「115年新的年度」說明文字 | 主席／值日生／主管與會來源，見下方「輪值表回填規則」 | **視情況**：不給的話主席/值日生要使用者自己用文字告知（config手動填`chair`/`duty_tue`/`duty_thu`/`boss_chairs_thu`）；要重排未來值日生輪值(`duty_rotation`)那次**必須**提供，因為要把結果寫回去。**這個分頁常常來自另一個獨立的Google Sheets檔案**（跟主要來源表不同檔），2026-09-14驗證過：分開檔案時腳本抓不到（`generate_agenda.py`只認`source_xlsx`裡的分頁），Claude要自己讀那個檔案的值後手動填四個config欄位；只有要用`duty_rotation`重排時才是硬限制——腳本Stage E需要輪值表分頁跟總表同一個活頁簿才能寫回存檔，分開來源檔目前不支援自動重排 |

識別後記住各分頁的實際名稱，後續讀取與腳本 config 都用實際名稱操作。

**來源取得（2026-11-03起）**：兩份都由 Claude 從開頭「固定來源」連結自動讀，使用者不用給檔案。輪值表與議程來源是不同檔，腳本抓不到，Claude 讀出當週主席／值日生／主管與會後填進 config 的 `chair`/`duty_tue`/`duty_thu`/`boss_chairs_thu`。

## 執行流程

### Step 1：識別分頁 → 讀取來源

從固定來源下載兩份檔，列出分頁名稱確認角色。讀到當週值日生後，先對照「已離職名單」，對到就跟使用者確認代班人。

### Step 2：自動比對上半場

從「重點專案」逐一比對「專案總表(正常報告版)」找出對應 PM：

**比對原則（Claude 語意判斷，不用 keyword 腳本）：**
- 以機構名稱 + 系統關鍵字比對（例：「機關甲…清查」→「機關甲_資產清查系統」）
- **年份視為區分依據**：同一機構若有 114年、115年兩個專案，年份不同 = 不同專案、不同 PM
- 比對來源不分週二/週四區段都要查——重點專案的PM本來就可能是週二PM（例：PM_D、PM_C正常只在週二報告）
- **有列管專案的人，整週都算「拉到週四」**：不論原本是週二PM還是週四PM，這個人本週**完全不出現在週二**，只在週四上半場報告列管專案；下半場也**不再重複列出他/她的其他非列管專案**——上半場報過就算報告完了，其他專案這週不用另外報
- **同一位PM這次可能有兩個以上列管專案**（例：PM_C同時有機關丙入口平臺+機關丁身分驗證系統）：`upper_order`裡這個人名字**只列一次**，他名下所有列管項目一起列在同一個時段格（`find_listed_items` 回傳 list）

比對完成後列出草稿請使用者確認：

```
[上半場草稿]
1. PM_A   → 機關甲_資產清查系統：成員B、成員A、成員C
2. PM_B    → 機關乙_人財會系統建置案：成員B、成員C、成員D
3. PM_C  → 機關丙_入口平臺：成員E、成員F、成員G、成員H
...（依序列出）

順序是否調整？有沒有要加入或移除的人？
```

### Step 3：互動確認

向使用者確認以下事項（已明確的不重複問）：

**A. 上半場順序調整**：使用者說「把 X 移到 Y 後面」即可，其餘不動

**B. 有無出差／請假的 PM**：依「請假／出差標註規則」處理，記下姓名、星期、類型（business_trip/leave）

**C. 週二／週四人員順序**：預設沿用總表原始順序，使用者告知需調整的部分才覆寫

**D. 主席是否本身也是當天報告PM**：若當週主席（見「輪值表回填規則」）剛好也在當天PM清單裡，跟使用者確認是否要排除他/她，目前腳本不會自動處理這種情況

**E. 本次會議日期**：週二＋週四各一個西元日期（例：`2026-09-01`／`2026-09-03`），用於抓輪值表、換算民國分頁名稱

**E2. 主席／值日生**：Claude 從固定來源的輪值表讀出本次主席、週二／週四值日生、週四是否主管與會（上半場改主管主持），填進 config；值日生在已離職名單裡才問使用者誰代

**F.（選用）是否要重排未來值日生輪值**：只有排除名單/離職異動時才需要，見「值日生輪值池與排除名單」

確認完畢，列出最終上下半場完整清單，再執行。

### Step 4：建立 config.json

```json
{
  "source_xlsx": "來源xlsx絕對路徑",
  "output_xlsx": "outputs/個人/1150903_PM會議議程.xlsx",
  "tue_date": "2026-09-01",
  "thu_date": "2026-09-03",
  "listed_projects": [
    "(2)機關戊_資料整合服務案：成員K、成員I、成員J、成員N、成員L"
  ],
  "upper_order": ["PM_A", "PM_B", "PM_C", "PM_D", "PM_E"],
  "tue_order_override": null,
  "lower_order_override": null,
  "absentees": [
    {"name": "PM_F", "day": "thu", "type": "leave"}
  ],
  "duty_rotation": null,
  "chair": "成員A",
  "duty_tue": "PM_G",
  "duty_thu": "PM_O",
  "boss_chairs_thu": true
}
```

- `listed_projects`：Step2比對出的總表原始列文字（**含開頭的`(n)`編號**，逐字比對），腳本會先清空總表D欄舊的「列管」標記再依這份清單重寫
- `absentees` 的 `type` 只能是 `business_trip` 或 `leave`，`day` 是 `tue` 或 `thu`
- `duty_rotation` 平常給 `null`；只有要重排未來值日生時才填（見「值日生輪值池與排除名單」的格式範例），且這種情況來源檔**一定要**附輪值表分頁
- `upper_proxies`（選用，2026-10-27新增）：列管項目掛在某PM名下、但由別人上台報告，例 `{"PM_J": {"owner": "PM_I", "keyword": "機關己"}}`，報告人名字放進`upper_order`
- `upper_text_override`（選用，2026-10-27新增）：週四轉貼分頁上半場的專案文字，例 `{"PM_B": ["機關乙_...：成員B、成員C、成員D", ...]}`；總表用語跟主管會議列管名稱不同時，沿用上週分頁的寫法
- 上半場時段：每項列管專案 10 分鐘（兩項就 20 分鐘，2026-10-27定案；腳本常數 MIN_PER_ITEM），PM會議 = 列管結束 +10 分鐘起排 60 分鐘；週四請假的上半場PM排最後、標「(本週請假)」、不佔時段（比照115-10-22分頁）
- `tue_cancelled`（選用，2026-11-03新增）：`true`＝週二會議取消，週二PM（扣掉上半場列管的人）全部併進週四下半場、排在週四PM前面，不產週二分頁
- `exclude_pms`（選用，2026-11-03新增）：已離職但總表還沒刪的PM，例 `["PM_H"]`
- `reassign`（選用，2026-11-03新增）：專案改掛別人名下（離職者專案分配），例 `[{"from": "PM_H", "to": "PM_K", "keyword": "機關庚"}]`，搭配 `exclude_pms` 把原PM剩下的專案一起拿掉
- `lower_extra`（選用，2026-11-03新增）：總表沒有、但要列在下半場的人，例 `[{"name": "PM_A", "items": ["機關辛_財產系統建置案：PM_J、成員A、成員M"]}]`，排序可用 `lower_order_override` 指定
- `chair`/`duty_tue`/`duty_thu`/`boss_chairs_thu`：輪值表是另一份檔，腳本讀不到，一律由 Claude 讀出後填入（必填，缺了腳本會報錯）

### Step 5：執行腳本

```bash
python .claude/skills/pm-weekly-agenda/scripts/generate_agenda.py <config_path>
```

腳本會一次做完：
1. 總表D欄「列管」標記重寫並驗證
2. 「專案議程」分頁整頁重寫（含橘色名字底色＋A~C欄框線，比照來源樣式；同一PM多個列管項目會一起列出）
3. 建立週二／週四兩個轉貼分頁（`{民國年月日}`為分頁名，格式比照`1150715`，**不含備註/連結區塊**，使用者自己補）
4. **自動清理超過一個月的歷史轉貼分頁**（以`thu_date`往前推30天為界）；固定的3個分頁（重點專案/專案總表/專案議程）跟輪值表分頁不會被清
5. **新分頁自動移到最前面**，緊接在固定3個分頁後面，讓分頁順序維持「最左邊最新、最右邊最舊」
6. （選用）重排輪值表未來值日生，含同週撞名自動偵測與互換

輸出路徑由 config 的 `output_xlsx` 決定；若無法歸屬到特定客戶/專案（PM議程通常屬此類），預設存 `outputs/個人/`。

## 格式範本（已內建，使用者不需每次提供）

- 議程版面／Header／footer／字型範本存於 `template/agenda_format_ref.json`（取自使用者提供的真實分頁 **1150715**，2026-08-31重建；此前 memory 曾記錄「範本已內建」但實際檔案不存在，已修正）。
- **週四**單欄 A 排版：Header(主席/值日生/請假) → 分隔線 → 時段區塊(列管報告/PM會議) → 上半場「列管專案報告」(PM名+時間 / 專案:人員) → 中場休息 → 下半場「PM會議」(PM名 / (1)(2)…) → 備註 footer。
- **週二**無列管/上下半場之分：Header → 分隔線 → 全部PM依總表順序列出，每人專案 (1)(2)… 編號 → 備註 footer（格式比照週四下半場，2026-08-31使用者確認）。
- 產出時：R1 改當週日期 `【115-MM-DD會議議程】`。**footer（備註事項、Google Drive／Zoom連結等）不預先帶入**——2026-08-31使用者指示：產出議程只做到PM清單為止，備註/連結區塊使用者自己補，Claude不要自動接續寫這段。
- **主席／值日生自動回填**：從來源 xlsx 的「115年(會議輪值表)」分頁抓取，規則見下方「輪值表回填規則」。
- 若來源 xlsx 內另有當期範本分頁（如 1150902），以該分頁為準覆寫此 JSON。

## 輪值表回填規則（主席／值日生／主管與會）

來源分頁「115年(會議輪值表)」欄位：A=日期、B=星期、D=值日生、F=主席、G=主管與會註記（每四週有兩次）。

- **主席延續整週**：主席只填在該週「週二」那一列（F欄），週四沿用同一人；若週四G欄有「主管與會」，該週四**上半場**改由主管主持，下半場仍是同一位主席。
  - 週四 header：`主席：上半場-主管、下半場-{同週二F欄的人}`（無主管與會時，整天就是同一位主席，不分上下半場）
  - 週二 header：`主席：{F欄}`
- **值日生逐日不同**：直接讀當天該列D欄。若D欄有「原名(代打名)」格式，取代打者的名字寫入header。

## 值日生輪值池與排除名單（會定期變動，每次執行前建議跟使用者確認是否有異動）

- **已離職名單**（讀輪值表/總表時遇到要主動處理）：PM_M、PM_H。總表還沒刪時用 `exclude_pms`，專案分配用 `reassign`，值日生問使用者誰代。使用者告知新的離職者時更新這行。

- 2026-08-31 使用者確認的排除名單：**PM_D、PM_B、PM_M、PM_F、PM_N、PM_A、PM_I** 不排未來值日生；PM_M 已離職。
- 週四值日生名額不足時（依上述排除後常態PM所剩無幾），使用者2026-08-31額外指示：可把當週「列管專案」的報告人也納入候補池（但仍排除PM_B、PM_A）。
- 排未來輪值時，**務必檢查同一週的週二/週四是否排到同一人**（同人一週值日兩次要避免），衝突時與下一筆順延互換。
- 這份排除名單綁定特定成員異動（離職/職務調整），每次真的要重排輪值表前，先跟使用者確認名單是否還正確，不要照抄舊 memory。

要重排時，config.json 的 `duty_rotation` 欄位格式：

```json
{
  "weekday": "四",
  "start_date": "2026-09-17",
  "end_date": "2026-12-31",
  "cycle": ["PM_E", "PM_O", "PM_H", "PM_P", "PM_C"]
}
```

`cycle` 是跟使用者確認好的輪值順序（依合格池 + 公平性，例如「誰最久沒真正輪過」判斷），腳本會從 `start_date` 到 `end_date` 之間所有 `weekday` 那一天依序循環套入，並自動檢查是否跟同週另一天撞名。

## 請假／出差 標註規則（2026-08-31使用者確認）

PM本次會議缺席時，在其名字旁加註記，並把該PM排到「當天清單最後一位」（不論總表原始順序）：

| 星期 | 情況 | 標註文字 |
|---|---|---|
| 週二 | 出差 | `(本週出差，改週四報告)` |
| 週四 | 出差 | `(本週出差，改上傳簡報摘要)` |
| 週二 | 請假 | `(本週請假)` |
| 週四 | 請假 | `(本週請假)` |

Header的「請假：」欄列出當次所有缺席者姓名（出差＋請假都算在內）；若無人缺席，該行整行省略。詳細規則同步存於 `template/agenda_format_ref.json` 的 `leave_business_trip_annotation_rules`。
